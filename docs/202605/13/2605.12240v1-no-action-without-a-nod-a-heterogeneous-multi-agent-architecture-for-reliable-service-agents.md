## 摘要
大语言模型（LLM）智能体日益推动了服务应用的发展，例如预订机票。然而，这些服务智能体在长程任务中存在不可靠性，因为它们经常产生策略违规、工具幻觉和动作失配，这极大地阻碍了它们的实际部署。为了应对这些挑战，我们提出了 NOD（Navigator-Operator-Director），一种用于服务智能体的异构多智能体架构。与以往工作中在对话上下文中隐式维护任务状态不同，我们将结构化的全局状态（Global State）外显化，以实现显式的任务状态跟踪和 Navigator 的一致性决策。此外，我们在关键动作之前引入了选择性的外部监督，允许独立的 Director 智能体验证执行并在必要时进行干预。因此，NOD 有效地缓解了长程任务中的错误传播和不安全行为。在 $τ^2$-Bench 上的实验表明，NOD 相比基准模型实现了更高的任务成功率和关键动作精度。更重要的是，NOD 通过减少策略违规、工具幻觉和用户意图失配，提高了服务智能体的可靠性。

## Abstract
Large language model (LLM) agents have increasingly advanced service applications, such as booking flight tickets. However, these service agents suffer from unreliability in long-horizon tasks, as they often produce policy violations, tool hallucinations, and misaligned actions, which greatly impedes their real-world deployment. To address these challenges, we propose NOD (Navigator-Operator-Director), a heterogeneous multi-agent architecture for service agents. Instead of maintaining task state implicitly in dialogue context as in prior work, we externalize a structured Global State to enable explicit task state tracking and consistent decision-making by the Navigator. Besides, we introduce selective external oversight before critical actions, allowing an independent Director agent to verify execution and intervene when necessary. As such, NOD effectively mitigates error propagation and unsafe behavior in long-horizon tasks. Experiments on $τ^2$-Bench demonstrate that NOD achieves higher task success rates and critical action precision over baselines. More importantly, NOD improves the reliability of service agents by reducing policy violations, tool hallucinations, and user-intent misalignment.

### 2. 方法论：NOD 架构
NOD 架构将智能体拆分为三个异构角色，并引入显式的全局状态管理：
*   **Navigator（导航员）**：负责维护**显式全局状态（Global State）**。该状态是一个结构化的 JSON 对象，包含用户意图、约束条件、缺失信息、子任务进度、实体信息和对话摘要。它解决了状态隐式化导致的遗忘问题。
*   **Operator（操作员）**：负责日常对话和提出动作建议。它基于 Navigator 提供的显式状态进行决策，而不是仅依赖原始对话历史。
*   **Director（导演/监督员）**：**核心创新点**。仅在 Operator 提出“关键动作”（如修改订单、扣费等改变外部环境的操作）之前介入。Director 会根据全局状态和上下文返回三种指令：
    *   **PASS**：允许执行。
    *   **REVISE**：拦截动作，要求 Navigator 更新状态并让 Operator 重新生成。
    *   **ABORT**：判定动作极度危险或无法修复，直接终止以防止损害。

### 6. 主要结论与发现
*   **性能提升**：NOD 在成功率（SR）上最高提升了 **23.7** 个百分点，在关键动作精准度（CAP）上提升了 **25.8** 个百分点。
*   **分工明确**：显式状态追踪（Navigator）显著提升了长对话下的控制力；REVISE 机制主要提升任务成功率，而 ABORT 机制主要提升动作安全性。
*   **架构优于模型**：即使全部使用 GPT-5.1，NOD 架构的表现依然优于 Vanilla GPT-5.1，证明了架构设计的独立价值。
*   **低频高效**：Director 仅在少数关键轮次触发，不会显著增加推理延迟或成本。

### 7. 优点
*   **解决状态漂移**：通过显式 JSON 状态强制模型保持对任务约束的记忆。
*   **异构监督**：引入 Director 作为“安全闸门”，有效拦截了工具幻觉和策略违规。
*   **高可靠性**：CAP 指标的引入非常符合工业界对服务智能体“宁可不做，不可做错”的要求。
*   **灵活性**：支持强弱模型搭配（Heterogeneous），在保证性能的同时兼顾成本。

### 8. 不足与局限
*   **状态维护开销**：Navigator 每轮都要重新生成完整的 JSON 状态，随着任务复杂度增加，Token 消耗和解析失败的风险会上升。
*   **领域依赖**：关键动作（Critical Actions）需要人工预定义，不同领域的迁移需要专家知识。
*   **实时性挑战**：虽然 Director 触发频率低，但在触发轮次需要多次模型调用，可能影响交互的实时响应感。
*   **实验范围**：目前仅在文本对话领域验证，尚未扩展到多模态或更开放的计算机操作场景。
