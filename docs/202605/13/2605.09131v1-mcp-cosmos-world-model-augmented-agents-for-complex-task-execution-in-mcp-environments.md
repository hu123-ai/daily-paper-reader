## 摘要
模型上下文协议（MCP）统一了大语言模型（LLM）与外部工具之间的接口，但在智能体如何概念化其运行环境方面仍存在根本性差距。当前的范式是分化的：任务级规划往往忽略执行时的动态变化，而反应式执行则缺乏长远预见。我们提出了 MCP-Cosmos，这是一个将生成式世界模型（WM）注入 MCP 生态系统的框架，旨在实现预测性任务自动化。通过统一 MCP、世界模型和智能体这三种不同的技术，我们证明了“自带世界模型”（BYOWM）策略允许智能体在执行前于潜空间中模拟状态转换并优化规划。我们在 20 多个 MCP-Bench 任务上，使用 ReAct 和 SPIRAL 两种策略，结合 2 个规划模型和 3 个代表性世界模型进行了实验。我们观察到智能体环境交互关键绩效指标（KPI）的提升，例如工具成功率和工具参数准确度。该框架还提供了诸如“执行质量”等新指标，以产生关于世界模型相较于基准线有效性的新见解。

## Abstract
The Model Context Protocol (MCP) has unified the interface between Large Language Models (LLMs) and external tools, yet a fundamental gap remains in how agents conceptualize the environments within which they operate. Current paradigms are bifurcated: Task-level planning often ignores execution-time dynamics, while reactive execution lacks long-horizon foresight. We present MCP-Cosmos, a framework that infuses generative World Models (WM) into the MCP ecosystem to enable predictive task automation. By unifying three disparate technologies, namely MCP, World Model, and Agent, we demonstrate that a "Bring Your Own World Model" (BYOWM) strategy allows agents to simulate state transitions and refine plans in a latent space before execution. We conducted experiments using two strategies, namely ReAct and SPIRAL with 2 planning models and 3 representative world models over 20+ MCP-Bench tasks. We observed improvements in Agent's environment interaction KPI such as tool success rate and tool parameter accuracy. The framework also offers new metrics such as Execution Quality to generate new insights about the effectiveness of world models compared to baseline.

论文针对当前基于**模型上下文协议（Model Context Protocol, MCP）**的智能体在执行复杂任务时存在的“视野短浅（Horizon Myopia）”问题展开研究。现有的智能体架构通常在两个极端之间摇摆：要么是纯规划导向（忽略执行时的动态环境），要么是纯反应式执行（如 ReAct，缺乏长远预见，导致冗余或不可逆的工具调用失败）。

**MCP-Cosmos** 的核心动机是引入**生成式世界模型（World Model, WM）**，使智能体具备“预测性认知”能力。通过在潜空间模拟工具调用的状态转移 $P(s_{t+1} | s_t, a_t)$，智能体可以在正式执行前进行前瞻性搜索和计划精炼，从而提高复杂环境下的任务成功率和执行效率。

#### 2. 论文提出的方法论
论文提出了 **BYOWM（Bring Your Own World Model，自带世界模型）** 架构，其核心思想是将世界模型集成到 MCP 交互循环中。

*   **核心流程（两阶段法）：**
    1.  **模拟规划阶段（Phase-1）：** 智能体 Planner 与世界模型交互。Planner 生成工具调用指令，世界模型在潜空间模拟该指令的返回结果（伪观测），而不实际触发外部环境。通过多次迭代或搜索（如 MCTS），生成一个经过验证的最优执行计划。
    2.  **实际执行阶段（Phase-2）：** 智能体按照预定计划在真实 MCP 环境中执行工具调用。若遇到意外失败，可选择性地触发计划调整机制。
*   **关键技术细节：**
    *   **抽象接口：** 定义了统一的 `WorldModel` 类，支持不同规模和类型的模型（如通用 LLM 或专门训练的 AWM）。

*   **数据集与场景：** 选用 **MCP-Bench** 作为主要基准，涵盖 28 个实时 MCP 服务器和 257 个跨域工具。实验重点选取了涉及 2-3 个服务器协作的复杂任务（共 24 个精选场景，300+ 条执行轨迹）。

    2.  **ReAct-Plan-Exec：** 结合世界模型进行前瞻规划的扩展版 ReAct。

    *   **世界模型（WM）：** GPT-OSS-120B, Claude-Sonnet-4.6, Arctic-AWM-4B（专门针对 MCP 环境微调的小模型）。

#### 5. 实验数量与充分性
*   **实验规模：** 进行了 300 多次轨迹测试，涵盖 12 种独特任务类型。
*   **充分性：** 实验设计较为全面，不仅对比了不同的智能体架构（ReAct vs SPIRAL），还对比了同质与异质的世界模型组合。

#### 6. 论文的主要结论与发现
*   **性能提升：** 引入世界模型后，智能体在**工具选择准确性**和**参数准确度**上显著优于 ReAct 基准。
*   **执行质量（Execution Quality）：** 论文发现 ReAct 虽然任务完成度尚可，但往往依赖大量的重试和错误调用。世界模型能显著减少无效工具调用，提高执行效率。
*   **规划器与 WM 的协同：** 强大的规划器（如 Claude）如果没有世界模型的约束，会倾向于在真实环境中进行过度探索（导致 Token 消耗和延迟激增）；世界模型能将这种“发散性探索”转化为“聚焦式执行”。
*   **模型能力差异：** 通用大模型作为世界模型的效果目前优于专门的小型 MCP 世界模型（Arctic-AWM-4B）。

#### 7. 优点
*   **架构灵活性：** BYOWM 策略允许开发者根据成本和性能需求灵活更换世界模型。
*   **新评估维度：** 提出了 **Execution Quality（执行质量）** 指标，综合考虑了成功率和调用次数，比单纯的“任务完成率”更贴近生产环境需求。
*   **解决痛点：** 有效缓解了智能体在处理具有副作用或高成本工具调用时的盲目性。

#### 8. 不足与局限
*   **计算开销：** 世界模型模拟显著增加了 Token 消耗（部分配置下比基准高出 5-6 倍），可能带来更高的成本和延迟。
*   **静态局限：** 当前的世界模型基于静态快照，无法实时感知 MCP 服务器环境的动态模式变化（如 API 更新）。
*   **指标局限性：** 新提出的“执行质量”指标依赖于实验组内的最大/最小调用次数进行归一化，这使得跨论文、跨实验的直接横向对比存在困难。
*   **模型表现：** 专门微调的 MCP 世界模型（4B 规模）在复杂逻辑预测上仍逊色于超大规模通用 LLM。
