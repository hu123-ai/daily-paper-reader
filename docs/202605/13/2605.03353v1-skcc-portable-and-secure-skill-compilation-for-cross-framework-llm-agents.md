## 摘要
大语言模型智能体（LLM-Agents）已演变为执行复杂任务的自主系统，SKILL.md 规范已成为封装智能体能力的事实标准。然而，一个关键瓶颈仍然存在：不同的智能体框架对提示词格式的敏感度差异巨大，导致性能波动高达 40%，但几乎所有技能都以单一的、与格式无关的 Markdown 版本存在。针对每个平台进行手动重写会带来不可持续的维护负担，而之前的审计发现，超过三分之一的社区技能包含安全漏洞。为了解决这一问题，我们提出了 SkCC，这是一个将经典编译器设计引入智能体技能开发的编译框架。其核心是 SkIR——一种强类型中间表示——它将技能语义与特定平台的格式解耦，从而实现在异构智能体框架间的可移植部署。围绕该中间表示，编译时分析器（Analyzer）在部署前通过“反技能注入”（Anti-Skill Injection）强制执行安全约束。通过四阶段流水线，SkCC 将适配复杂度从 $O(m \times n)$ 降低到 $O(m + n)$。在 SkillsBench 上的实验表明，编译后的技能表现始终优于原始版本，在 Claude Code 上的通过率从 21.1% 提高到 33.3%，在 Kimi CLI 上从 35.1% 提高到 48.7%，同时实现了低于 10ms 的编译延迟、94.8% 的主动安全触发率，以及在不同平台上节省了 10-46% 的运行时 Token。

## Abstract
LLM-Agents have evolved into autonomous systems for complex task execution, with the SKILL.md specification emerging as a de facto standard for encapsulating agent capabilities. However, a critical bottleneck remains: different agent frameworks exhibit starkly different sensitivities to prompt formatting, causing up to 40% performance variation, yet nearly all skills exist as a single, format-agnostic Markdown version. Manual per-platform rewriting creates an unsustainable maintenance burden, while prior audits have found that over one third of community skills contain security vulnerabilities. To address this, we present SkCC, a compilation framework that introduces classical compiler design into agent skill development. At its core, SkIR - a strongly-typed intermediate representation - decouples skill semantics from platform-specific formatting, enabling portable deployment across heterogeneous agent frameworks. Around this IR, a compile-time Analyzer enforces security constraints via Anti-Skill Injection before deployment. Through a four-phase pipeline, SkCC reduces adaptation complexity from $O(m \times n)$ to $O(m + n)$. Experiments on SkillsBench demonstrate that compiled skills consistently outperform their original counterparts, improving pass rates from 21.1% to 33.3% on Claude Code and from 35.1% to 48.7% on Kimi CLI, while achieving sub-10ms compilation latency, a 94.8% proactive security trigger rate, and 10-46% runtime token savings across platforms.

随着大语言模型（LLM）智能体的发展，**技能（Skills）**已成为封装领域知识和工具调用逻辑的标准方式（如 `SKILL.md` 规范）。然而，当前生态面临两大核心瓶颈：
*   **格式敏感性（Format Sensitivity）：** 不同的智能体框架（如 Claude Code, OpenAI Codex, Gemini CLI, Kimi CLI）对提示词格式的偏好迥异（如 Claude 偏好 XML，GPT 偏好 XML-Tagged Markdown）。现有的“一处编写，到处运行”的 Markdown 技能在不同平台上性能波动高达 40%。
*   **安全风险：** 审计显示超过 1/3 的社区技能存在安全漏洞或恶意负载，且缺乏系统性的编译时安全检查。
*   **维护负担：** 为 $M$ 个技能适配 $N$ 个平台需要 $O(M \times N)$ 的手动重写工作量。

**SkCC** 的提出旨在通过引入经典编译器设计理念，将技能语义与平台格式解耦，实现 $O(M + N)$ 的开发效率提升，并同步增强安全性。

#### 2. 方法论：核心思想与关键技术
SkCC 设计了一个**四阶段编译流水线**，其核心思想是引入强类型的中间表示（IR）：
1.  **前端（Frontend）：** 解析原始 `SKILL.md`，将 YAML 元数据与 Markdown 正文分离，构建抽象语法树（AST）。
2.  **IR 构建（IR Construction）：** 将 AST 转换为 **SkIR**（一种强类型、平台无关的中间表示）。SkIR 涵盖元数据、接口（MCP 协议）、安全控制、执行逻辑等六大类信息，并能自动检测嵌套数据深度以优化格式选择。
3.  **分析器（Analyzer）：** 进行语义验证和**安全加固**。核心技术是**反技能注入（Anti-Skill Injection）**，通过 AST 遍历自动识别危险模式（如无限制循环、危险数据库操作、不安全的 HTTP 请求），并强制注入防御性约束。
4.  **后端（Backend）：** 多靶点发射器（Emitters）。根据目标模型的训练分布偏好，将 SkIR 转换为特定格式（如 Claude 的 XML 语义层、Gemini 的 Markdown+YAML 混合格式等）。
