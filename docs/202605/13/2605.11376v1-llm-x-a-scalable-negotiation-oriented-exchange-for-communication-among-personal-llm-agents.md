## 摘要
我们提出了个人 LLM 交换平台 (LLM-X)，这是一个可扩展的、面向协商的环境，能够实现代表不同用户的个人智能体（LLM）群体之间的直接、结构化通信。与现有的侧重于智能体与 API 交互的以工具为中心的协议不同，LLM-X 引入了消息总线和路由底层架构，用于 LLM 之间的协作，并提供模式有效性和策略执行方面的保证。我们的贡献包括：(1) LLM-X 架构，由联邦网关、基于主题的路由和策略执行组成；(2) 一种支持能力协商和合同网式协作的有类型消息协议；以及 (3) 对大规模基于 LLM 的多智能体协商进行的首次实证评估。实验涵盖了 5、9 和 12 个智能体，在不同的协商策略（低、中、高）下，以及短期（分钟级）和长期（2 小时、12 小时）负载条件下进行。结果突显了明显的策略-性能权衡：更严格的策略提高了鲁棒性和公平性，但增加了延迟和消息量。长期运行证实，LLM-X 在持续负载下保持稳定，且延迟漂移在有限范围内。

## Abstract
We propose a personal-LLM exchange (LLM-X), a scalable negotiation-oriented environment that enables direct, structured communication across populations of personal agents (LLMs), each representing an individual user. Unlike existing tool-centric protocols that focus on agent-API interaction, LLM-X introduces a message bus and routing substrate for LLM-to-LLM coordination with guarantees around schema validity and policy enforcement. We contribute: (1) an architecture for LLM-X comprising federated gateways, topic-based routing, and policy enforcement; (2) a typed message protocol supporting capability negotiation and contract-net-style coordination; and (3) the first empirical evaluation of LLM-based multi-agent negotiation at scale. Experiments span 5, 9, and 12 agents, under distinct negotiation policies (Low, Medium, High), and across both short-run (minutes) and long-run (2h, 12h) load conditions. Results highlight clear policy-performance trade-offs: stricter policies improve robustness and fairness but increase latencies and message volume. Extended runs confirm that LLM-X remains stable under sustained load, with bounded latency drift.

#### 1. 核心问题与研究动机
当前的个人大语言模型（LLM）助手大多处于“孤岛”状态，主要通过工具或 API 与系统交互，缺乏智能体与智能体（Agent-to-Agent）之间直接、结构化且可扩展的通信机制。这种隔离限制了多智能体在复杂任务中的协商、规划和共识达成。论文旨在填补这一空白，提出一个名为 **LLM-X** 的基础设施，为异构 LLM 智能体提供一个支持模式验证（Schema Validation）和策略执行的通信基座，使其能够像人类一样进行复杂的合同协商。

#### 2. 方法论：核心思想与关键技术
LLM-X 的核心思想是建立一个**面向协商的消息总线和路由底层架构**。其关键技术细节包括：
*   **分层架构**：
    *   **联邦网关（Gateways）**：负责身份验证（JWT）、JSON 模式验证和速率限制，确保消息合法且符合预定义格式。
    *   **策略引擎（Policy Engine）**：定义了三种协商策略（Low, Medium, High），控制智能体如何处理竞争性报价（Offer）。
    *   **控制平面与观测性**：管理智能体注册、能力协商及详细的指标追踪（延迟、吞吐量等）。
*   **通信协议**：
    *   **合同网（ContractNet）模式**：采用“招标（CFP）→ 报价（Offer）→ 接受/拒绝（Accept/Reject）→ 确认（Ack）”的结构化流程。
    *   **FIPA 交互式报价**：支持两个智能体之间基于截止日期的往复式提案交换。
*   **消息模型**：使用类型化的 JSON 信封，包含元数据（ID、发送者、能力、TTL）和符合特定 Schema 的有效载荷，确保不同 LLM 厂商（如 OpenAI, Anthropic）生成的输出能被统一解析。

#### 3. 实验设计
实验旨在评估 LLM-X 在不同规模和策略下的性能表现：

    *   **Medium 策略**：一旦收到首个有效响应立即成交并关闭。
    *   **High 策略**：必须收集所有报价后才进行决策，确保公平和完整。
*   **基准指标**：每分钟消息量（CFP/Offer）、中值延迟（p50）、尾部延迟（p95）、轮次完成率及系统稳定性。

#### 6. 主要结论与发现
*   **策略-性能权衡**：更严格的策略（High）能保证 100% 的轮次完整性和公平性，但会显著增加消息量和同步开销；较松散的策略（Medium/Low）响应更快，但可能导致协商不充分。
*   **线性扩展性**：随着智能体数量从 5 增加到 12，消息流量呈近线性增长，而延迟增加保持在毫秒级的可控范围内。
*   **长期稳定性**：在 12 小时的持续负载下，LLM-X 未出现明显的延迟漂移或系统饱和，证明了异步网关架构的可靠性。
*   **延迟特征**：系统主要受 CPU 限制而非 I/O 限制，平均延迟稳定在 6ms 左右。

#### 7. 优点
*   **架构解耦**：将协商逻辑（策略引擎）与底层通信（NATS/HTTP）分离，具有极高的灵活性。
*   **LLM 就绪性**：通过 JSON Schema 强制约束，解决了 LLM 输出随机性与工业级协议严谨性之间的矛盾。
*   **可观测性强**：提供了详细的审计日志和追踪机制，为多智能体系统的可解释性提供了基础。

#### 8. 不足与局限
*   **智能体真实性**：当前实验主要基于 Python 脚本模拟的载荷，尚未在大规模真实 LLM API 调用（存在网络抖动和推理延迟）环境下进行深度验证。
*   **语义复杂度**：实验中的协商内容相对简单，尚未涉及 LLM 在复杂法律或商业条款协商中的推理能力对通信效率的影响。
*   **安全防御**：虽然提到了模式验证可缓解提示词注入，但针对更高级的针对性攻击（如恶意协商策略）的防御机制尚待完善。
