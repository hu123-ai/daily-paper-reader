## 摘要
工具调用智能体通常根据工具选择、参数准确性和范围识别进行评估，但大语言模型（LLM）的轨迹评估本质上仍是事后的。由于与活跃的执行循环脱节，此类评估识别出的错误通常通过提示词微调或重新训练来解决，且从根本上无法实时纠正智能体的行为。为了弥补这一差距，我们将评估移至推理时的执行循环中：一个专门的审查智能体在执行前评估临时的工具调用，将范式从后期恢复转变为主动评估和错误缓解。在实践中，这种架构在主执行智能体和次要审查智能体之间建立了明确的关注点分离。与任何多智能体系统一样，审查者在纠正错误的同时也可能引入新错误，但据我们所知，此前尚无研究系统地衡量这种权衡。为了量化这种权衡，我们引入了“益处-害处”（Helpfulness-Harmfulness）指标：益处衡量反馈纠正基础智能体错误的百分比；害处衡量反馈导致正确响应退化的百分比。这些指标通过揭示给定模型或提示词是否提供净正向价值，直接指导审查者的设计。我们在 BFCL（单轮）和 Tau2-Bench（多轮有状态场景）上评估了我们的方法，在无关性检测上提升了 5.5%，在多轮任务上提升了 7.1%。我们的指标表明，审查者模型的选择至关重要：推理模型 o3-mini 实现了 3:1 的收益风险比，而 GPT-4o 为 2.1:1。通过 GEPA 进行的自动提示词优化额外带来了 1.5-2.8% 的提升。总之，这些结果证明了分离执行与审查的核心优势：可以通过模型选择和提示词优化系统地改进审查者，而无需重新训练基础智能体。

## Abstract
Tool-calling agents are evaluated on tool selection, parameter accuracy, and scope recognition, yet LLM trajectory assessments remain inherently post-hoc. Disconnected from the active execution loop, such assessments identify errors that are usually addressed through prompt-tuning or retraining, and fundamentally cannot course-correct the agent in real time. To close this gap, we move evaluation into the execution loop at inference time: a specialized reviewer agent evaluates provisional tool calls prior to execution, shifting the paradigm from post-hoc recovery to proactive evaluation and error mitigation.   In practice, this architecture establishes a clear separation of concerns between the primary execution agent and a secondary review agent. As with any multi-agent system, the reviewer can introduce new errors while correcting others, yet no prior work to our knowledge has systematically measured this tradeoff. To quantify this tradeoff, we introduce Helpfulness-Harmfulness metrics: helpfulness measures the percentage of base agent errors that feedback corrects; harmfulness measures the percentage of correct responses that feedback degrades. These metrics directly inform reviewer design by revealing whether a given model or prompt provides net positive value.   We evaluate our approach on BFCL (single-turn) and Tau2-Bench (multi-turn stateful scenarios), achieving +5.5% on irrelevance detection and +7.1% on multi-turn tasks. Our metrics reveal that reviewer model choice is critical: the reasoning model o3-mini achieves a 3:1 benefit-to-risk ratio versus 2.1:1 for GPT-4o. Automated prompt optimization via GEPA provides an additional +1.5-2.8%. Together, these results demonstrate a core advantage of separating execution and review: the reviewer can be systematically improved through model selection and prompt optimization, without retraining the base agent.

以下是对该论文的结构化总结：

### 1. 核心问题与研究动机
*   **核心问题**：现有的工具调用智能体在选择工具、构造参数或识别“无相关工具”时经常出错。
*   **研究动机**：
    *   **事后评估的局限性**：目前的评估多为执行后的分析，无法在错误发生时实时纠偏。
    *   **状态恢复难题（State Recovery Problem）**：一旦智能体执行了错误操作（如误删数据），在复杂的多轮对话中恢复到正确状态的成本极高且极具挑战。
    *   **训练成本**：通过强化学习（如 GRPO）或微调来改进智能体需要巨大的算力和漫长的部署周期。
*   **整体含义**：将评估环节从“事后”移至“推理时执行循环内”，通过引入专门的“审阅者”智能体，在工具真正执行前拦截并纠正潜在错误。

### 2. 方法论
核心思想是**关注点分离（Separation of Concerns）**，将系统分为“主执行智能体”和“次要审阅智能体”。
*   **三种协作机制**：
    1.  **渐进式反馈（Progressive Feedback, $r_N$）**：审阅者评估初步调用，若有错则提供反馈，执行者据此修改，循环最多 $N$ 次。
    2.  **N 选 1 选择（Best-of-N Selection, $s_N$）**：执行者生成 $N$ 个候选调用，审阅者直接选出最佳的一个。
    3.  **N 选 1 评分（Best-of-N Grading, $g_N$）**：审阅者对 $N$ 个候选调用进行打分（0-1.0）并给出理由，选择得分最高者。
*   **关键技术细节**：
    *   **益处-害处指标（Helpfulness-Harmfulness Metrics）**：量化反馈的质量。益处指纠正了多少错误；害处指误导了多少原本正确的调用。
    *   **自动提示词优化（APO）**：利用 **GEPA**（遗传-帕累托提示词演化）算法，通过观察审阅者的失败案例，自动迭代优化审阅者的提示词，使其更严谨。

### 3. 实验设计
*   **数据集/场景**：
    *   **BFCL (Berkeley Function Calling Leaderboard)**：评估单轮、无状态的工具调用（包括简单、多重、并行及无关性检测）。
    *   **$\tau^2$-Bench**：评估多轮、有状态的复杂场景（涵盖航空、零售、电信三个领域），需遵循特定领域政策。

    *   **审阅模型对比**：对比了非推理模型（GPT-4o）与推理模型（o3-mini, GPT-5 mini）作为审阅者的效果。
    *   **机制对比**：对比了上述 $r_N, s_N, g_N$ 三种协作模式。

### 5. 实验数量与充分性
*   **实验规模**：
    *   在 BFCL 上进行了上万次调用测试（Baseline $n=10,923$）。

### 6. 主要结论与发现
*   **性能提升**：在 BFCL 无关性检测上提升了 **5.5%**，在 $\tau^2$-Bench 多轮任务上平均提升了 **7.1%**。
*   **模型选择至关重要**：推理模型（o3-mini）作为审阅者表现远优于标准模型，其收益风险比达到 **3:1**（纠正 3 个错误才误伤 1 个正确调用），而 GPT-4o 仅为 2.1:1。
*   **自动优化的威力**：通过 GEPA 优化的提示词比人工编写的提示词在相关性任务上额外提升了 1.5%-2.8%。
*   **延迟代价**：推理时反馈会增加延迟。单轮任务延迟增加约 6.2 倍，但在多轮任务中，由于开销被分摊，延迟增加仅为 2.4 倍。

### 7. 优点
*   **无需重训**：提供了一种即插即用的方案，无需修改基础模型权重即可提升性能。
*   **主动防御**：在执行前拦截错误，有效解决了破坏性操作后的状态恢复难题。
*   **量化框架**：提出的“益处-害处”指标为评估多智能体协作中的“负迁移”提供了清晰的标准。
*   **模块化**：审阅者可以独立于执行者进行升级或更换。

### 8. 不足与局限
*   **延迟开销**：对于实时性要求极高的单轮应用，6.2 倍的延迟增加可能难以接受。
*   **模型范围有限**：实验主要集中在 GPT 系列模型，尚未验证该架构在开源模型（如 Llama, Mistral）上的泛化能力。
*   **领域偏差**：在 $\tau^2$-Bench 中发现，针对 BFCL 优化的提示词直接迁移效果不佳，说明审阅者仍需针对特定领域进行一定的提示词适配。
*   **成本增加**：引入额外的审阅智能体意味着更高的 API 调用成本。
