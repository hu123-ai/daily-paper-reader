## 摘要
大语言模型导师在 Notebook 环境中易于构建，但在实际课程中却难以运行。我们描述了 ITAS（智能助教系统），这是一个在奥多明尼昂大学的研究生量子计算课程中应用了一个学期的多智能体辅导系统。该系统包含三层：教学层采用轮辐式（Spoke-and-Wheel）结构，由三个并行的专家智能体（视频、代码、指导）及随后的合成器组成，此外还有一个独立的自动评分器，用于评估检查点提交内容的正确性和方法；运行层由四个 Cloud Run 微服务组成，会话状态存储在 Cloud SQL 中，交互事件通过 Pub/Sub 流式传输到 BigQuery；反馈层是一个窄域对话智能体，它根据每节课的匿名化事件流回答教师的问题，旨在解决我们所谓的“盲师问题”（Blind Instructor Problem），即大语言模型导师积累的学生数据超出了教师通过常规渠道所能获取的范围。该架构是对早期原型特定失败的直接回应，我们描述了哪些修复方案被沿用，哪些在本次迭代中被舍弃。我们报告了一次试点部署（5名学生，1门课程，1个学期），其结果被视为系统行为证据而非学习成果证据：教学层处理了 334 轮对话，且未出现领域整合可能带来的任务边界幻觉；运行层在五个模块中捕获了 10,628 个事件；反馈层发现了两项结果，教师在学期中据此采取了行动。我们并不声称该试点具有普适性，但我们认为，所描述的系统是针对基于大语言模型的智能教学系统（ITS）在实际课程中端到端运行所需形态的一个可行答案。

## Abstract
Large language model tutors are easy to build in a notebook and hard to run in a real course. We describe ITAS (Intelligent Teaching Assistant System), a multi-agent tutoring system that a graduate quantum computing course used for a semester at Old Dominion University. The system has three layers. The teaching layer is a Spoke-and-Wheel of three parallel specialist agents (Video, Code, Guidance) followed by a Synthesizer, plus a separate autograder that evaluates both the correctness and the approach of checkpoint submissions. The operational layer is four Cloud Run microservices with session state in Cloud SQL and interaction events streamed through Pub/Sub to BigQuery. The feedback layer is a narrow-scope conversational agent that answers instructor questions over per-lesson pseudonymized event streams, addressing what we call the Blind Instructor Problem: LLM tutors accumulate more data about students than the instructor can reach through routine channels. The architecture is a direct response to specific failures of an earlier prototype, and we describe which of those fixes carried forward and which were dropped for this iteration. We report on a pilot deployment (five students, one course, one semester) interpreted as system-behavior evidence rather than learning-outcome evidence: the teaching layer handled 334 chat turns without the task-boundary hallucinations that domain consolidation would have risked, the operational layer captured 10,628 events across five modules, and the feedback layer surfaced two findings the instructor acted on mid-semester. We do not claim the pilot generalizes. We do claim that the system as described is one workable answer to the question of what an LLM-based ITS needs to look like end-to-end to run in a real course.

### 1. 核心问题与研究动机
*   **研究背景**：虽然在 Notebook 环境中构建大语言模型（LLM）导师很容易，但在真实的教学场景中运行却面临巨大挑战。
*   **核心问题**：
    *   **认知过载与幻觉**：单一智能体在同时处理教学规划、知识讲解、代码调试和进度控制时，容易产生工具调用错误或进度跳跃。
    *   **盲师问题（Blind Instructor Problem）**：LLM 导师在与学生交互中积累了海量细粒度数据，但教师无法通过传统渠道有效获取和利用这些信息，导致教学反馈滞后。
*   **研究目标**：设计一个能够端到端运行在真实课程中、具备高可靠性且能为教师提供深度洞察的多智能体架构。

### 2. 方法论：ITAS 三层架构
ITAS 采用了分层设计，将教学逻辑、基础设施和教师反馈解耦：

*   **教学层（Teaching Layer）- 轮辐式（Spoke-and-Wheel）架构**：
    *   **并行专家智能体**：包含三个专门的智能体：**视频智能体**（负责视频内容检索）、**代码智能体**（负责诊断错误，不直接给出答案）和**指导智能体**（负责概念解释和苏格拉底式引导）。
    *   **合成器（Synthesizer）**：读取三个专家智能体的结构化输出（基于 Pydantic 校验），汇总生成最终的自然语言回复。
    *   **自动评分器（Autograder）**：独立于对话流，评估学生提交的代码是否在“结果正确性”和“实现方法”上均符合要求。
*   **运行层（Operational Layer）**：
    *   基于 Google Cloud Platform 的微服务架构，使用 Cloud Run 部署四个核心服务（教学、执行、分析、评分）。
    *   使用 Cloud SQL 维护会话状态，通过 Pub/Sub 将交互事件流式传输至 BigQuery。
*   **反馈层（Feedback Layer）**：
    *   **对话式分析智能体**：教师通过自然语言询问学生进度。该智能体仅读取匿名化的事件流和课程元数据，不具备写 SQL 或直接访问身份信息的权限，确保隐私安全（符合 FERPA 标准）。

### 5. 实验数量与充分性
*   **实验规模**：捕获了 10,628 个交互事件，处理了 334 轮聊天对话，涵盖 5 个教学模块。
*   **充分性评价**：作为“系统可行性”研究，其实验涵盖了完整的学期周期，数据量足以证明架构的稳定性。但由于样本量极小（N=5），且缺乏对照组（Control Group），其在“教学有效性”和“普适性”上的验证尚不充分。

### 6. 主要结论与发现
*   **架构有效性**：通过“领域分解”而非“任务分解”，成功消除了早期原型中常见的任务边界幻觉（例如代码智能体不再错误引用视频时间戳）。
*   **解决盲师问题**：反馈层成功帮助教师发现了教学盲点（如学生在视频 42 分钟后参与度骤降，因为后续内容与考核点脱节），并促使教师在中期修改了课程设计。
*   **隐私合规**：证明了通过架构设计（而非仅靠 Prompt 约束）可以实现符合 FERPA 要求的教育数据处理。

### 7. 优点与亮点
*   **领域分解思想**：将 LLM 的推理压力分散到特定领域的专家智能体上，显著提升了回复的逻辑性和准确性。
*   **端到端落地**：不仅停留在算法层面，还详细描述了云端微服务、会话持久化和数据流转的工程实现。
*   **反馈层创新**：将复杂的学习分析（Learning Analytics）转化为简单的自然语言对话，降低了教师使用数据的门槛。

### 8. 不足与局限
*   **样本量极小**：仅 5 名学生参与，无法进行统计学意义上的学习效果分析。
*   **自设计偏差**：课程开发者与系统开发者为同一人，可能存在课程内容高度适配系统的偏差。
*   **缺乏自动化评估**：反馈层生成的洞察报告尚未经过专家评分员的严格一致性校验。
*   **依赖特定模式**：该系统目前高度适配“翻转课堂”和“STEM 编程类”课程，在人文社科等非结构化较强的学科中应用效果未知。
