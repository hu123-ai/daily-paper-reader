## 摘要
基于大语言模型（LLM）的多智能体系统在软件工程、预测建模和检索增强生成等复杂的现实任务中表现出了强大的性能。然而，由于评分仅在系统层面可用，而控制智能体行为的参数是局部的，因此其配置的自动化仍然是一个结构性挑战。我们认为，优化这些系统从根本上说是一个信用分配（credit-assignment）问题。因此，我们提出了 CANTANTE，这是一个通过对比同一查询下多个联合配置的运行结果（rollouts），将系统级奖励分解为每个智能体更新信号的框架。我们将其应用于提示词优化，将智能体提示词视为可学习的系统参数。我们在编程（MBPP）、数学推理（GSM8K）和多跳问答（HotpotQA）任务上，将 CANTANTE 与 GEPA 和 MIPROv2 进行了对比评估。在这些基准测试中，CANTANTE 在所有评估的优化器中获得了最佳的平均排名，并始终优于未优化的提示词。在 MBPP 上，它比最强的基准模型提高了 18.9 个百分点，在 GSM8K 上提高了 12.5 个百分点，同时推理成本更低。在 HotpotQA 上，它的表现与最强基准模型的差距保持在一个标准差之内。至关重要的是，我们的信用相关性分析证实，归因器产生了有意义的单智能体信号，而不是简单地重复全局系统评分。

## Abstract
LLM-based multi-agent systems have demonstrated strong performance across complex real-world tasks, such as software engineering, predictive modeling, and retrieval-augmented generation. Yet automating their configuration remains a structural challenge, as scores are available only at the system level, whereas the parameters governing agent behavior are local. We argue that optimizing these systems is fundamentally a credit-assignment problem. We therefore introduce CANTANTE, a framework that decomposes system-level rewards into per-agent update signals by contrasting rollouts of multiple joint configurations on the same query. We instantiate it for prompt optimization, treating agent prompts as learnable system parameters. We evaluate CANTANTE against GEPA and MIPROv2 on programming (MBPP), mathematical reasoning (GSM8K), and multi-hop question answering (HotpotQA). Across these benchmarks, CANTANTE achieves the best average rank among all evaluated optimizers and consistently outperforms unoptimized prompts. It improves over the strongest baseline by +18.9 percentage points on MBPP and +12.5 percentage points on GSM8K, while incurring a lower inference cost. It remains within one standard deviation of the strongest baseline on HotpotQA. Crucially, our credit correlation analysis confirms that the attributer produces meaningful per-agent signals rather than echoing the global system score.

### 1. 核心问题与整体含义（研究动机和背景）
*   **核心问题**：基于大语言模型（LLM）的多智能体系统（MAS）虽然强大，但其配置（如提示词、角色分配）主要依赖人工调试。自动优化的难点在于**信用分配（Credit Assignment）**的结构性失配：评估反馈是系统级的全局标量（如“任务是否完成”），而待优化的参数是局部的（每个智能体各自的提示词）。
*   **研究背景**：现有的优化方法（如 MIPROv2 或 GEPA）通常将全局得分直接传播给所有智能体，或者采用轮询式更新，这无法准确识别哪个智能体对最终结果贡献最大或导致了失败。

### 2. 方法论：CANTANTE 框架
*   **核心思想**：引入**对比式组内归因（Contrastive In-Group Attribution）**。通过在同一个查询（Query）下运行多个不同的智能体配置组合，利用一个“归因模型”（Attributer LLM）对比这些运行轨迹（Trajectories）的差异，从而将全局奖励分解为每个智能体的局部信用信号。
*   **关键技术细节**：
    1.  **配置采样**：每个智能体的局部优化器提出 $K$ 个候选参数，组合成 $K$ 个联合配置。
    2.  **并行评估**：在任务数据集上运行这些配置，获取系统得分和执行轨迹。
    3.  **对比归因**：归因模型接收同一查询下的多个轨迹和得分，通过对比分析（例如：为什么配置 A 成功而配置 B 失败？是哪个环节的输出导致了差异？），为每个智能体分配 $[-1, +1]$ 范围内的信用值。
    4.  **局部更新**：将归因后的信用信号反馈给各智能体的局部优化器（默认使用 CAPO），进行下一轮迭代。
*   **算法优势**：该方法独立于具体的局部优化器，且在系统得分相同（如都失败）的情况下，仍能通过分析中间推理轨迹提供有意义的改进信号。

### 3. 实验设计
*   **数据集与场景**：
    *   **MBPP (编程)**：使用包含“计划者-执行者-验证者”的条件循环图。
    *   **GSM8K (数学推理)**：使用包含三个并行“执行者”和一个“共识智能体”的集成图。
    *   **HotpotQA (多跳问答)**：使用包含检索、阅读、合成和幻觉检测的 RAG 工作流图。
*   **对比方法（Baselines）**：
    *   **Initial**：未经优化的初始提示词。
    *   **GEPA**：基于反射式提示词演化的优化器。
    *   **MIPROv2**：基于贝叶斯优化的多智能体提示词优化器。

### 4. 资源与算力
*   **硬件**：实验在 **NVIDIA L40 GPU** 上运行。
*   **算力消耗**：主实验耗时约 **100 GPU 小时**，消融实验耗时约 **30 GPU 小时**，总计约 **130 GPU 小时**。
*   **模型使用**：下游任务智能体使用 **Qwen3-30B**，优化器和归因模型使用 **GPT-OSS-120B**。

### 5. 实验数量与充分性
*   **实验规模**：在 3 个不同拓扑结构的基准测试上进行了评估，每个实验运行 3 个随机种子并计算标准差。
*   **消融实验**：非常充分。涵盖了归因组件（对比 vs. 直接传播全局分）、归因模型/提示词的敏感性、局部优化器的更换、对比组大小（Group Size）、以及训练集规模（低数据状态下的表现）等多个维度。
*   **公平性**：所有优化器共享相同的 10M Token 优化预算，并对基准模型（MIPROv2）在某些情况下给予了额外的预算以确保对比的严谨性。

### 6. 主要结论与发现
*   **性能领先**：CANTANTE 在所有评估的优化器中平均排名第一。在 MBPP 上比最强基准提升 **18.9%**，在 GSM8K 上提升 **12.5%**。
*   **推理效率**：在提升准确率的同时，CANTANTE 优化后的提示词在 MBPP 和 GSM8K 上的推理 Token 成本反而低于初始提示词，证明其改进源于更精准的指令而非单纯增加推理长度。
*   **归因有效性**：信用相关性分析证实，归因模型能够识别出系统中的关键瓶颈（如 MBPP 中的验证者智能体），产生的信号具有高度的诊断价值。

### 7. 优点与亮点
*   **解耦设计**：将“信用分配”与“参数更新”解耦，使其可以作为插件应用于各种现有的提示词优化器。
*   **对比机制**：通过组内对比克服了 LLM 难以给出绝对评分的弱点，使优化在奖励稀疏或全零的情况下依然能进行。
*   **鲁棒性**：实验证明该方法对归因模型和提示词的选择不敏感，且在小样本（75 个样本）下依然有效。

### 8. 不足与局限
*   **拓扑固定**：目前仅优化智能体的参数（提示词），不涉及工作流拓扑结构（图结构）的自动修改。
*   **归因模型依赖**：归因质量受限于所使用的 LLM 能力。如果归因模型弱于下游智能体，可能会提供错误的指导信号。
*   **可扩展性挑战**：随着智能体数量增加，归因模型需要处理的轨迹长度会呈指数增长，可能面临上下文窗口限制或信息过载。
*   **额外开销**：引入归因步骤会消耗额外的优化预算（Token），虽然实验证明这部分投入是值得的。
