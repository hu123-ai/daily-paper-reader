## 摘要
大语言模型（LLM）智能体在处理多步任务时日益依赖技能库，然而，随着技能的添加、重用、修补以及与不断变化的依赖项关联，这些库可能会积累持久性缺陷。我们将这种故障模式称为“技能技术债”：即库级别的缺陷，它们可能不会在局部破坏单个技能，但会损害未来的检索、组合和执行。现有的基于技能的智能体主要关注任务时的检索、规划和修复，而库时的维护仍未得到充分探索。我们提出了 SkillOps，这是一个用于维护技能库的与方法无关的插件框架。SkillOps 将每个技能表示为有类型的技能合约（Skill Contract，P, O, A, V, F），利用分层技能生态图（Hierarchical Skill Ecosystem Graph）组织技能，并从效用、兼容性、风险和验证维度诊断库的健康状况。给定一个原始技能库，SkillOps 会生成一个经过维护的库，现有的检索或规划智能体无需更改其内部代码即可使用该库。在 ALFWorld 上，SkillOps 作为独立智能体实现了 79.5% 的任务成功率，在不增加额外任务时大语言模型调用的情况下，比最强的基准模型高出 8.8 个百分点。作为插件层，它将重检索基准模型的性能提升了 0.68 到 2.90 个百分点。目前基于规则的维护实现几乎不使用库时的大语言模型调用或 Token，这表明技能库维护可以作为一个低开销的架构层添加。

## Abstract
Large language model agents increasingly rely on skill libraries for multi-step tasks, yet these libraries can accumulate persistent defects as skills are added, reused, patched, and linked to changing dependencies. We call this failure mode skill technical debt: library-level defects that may not break a single skill locally but can harm future retrieval, composition, and execution. Existing skill-based agents mainly focus on task-time retrieval, planning, and repair, while library-time maintenance remains underexplored. We propose SkillOps, a method-agnostic plug-in framework for maintaining skill libraries. SkillOps represents each skill as a typed Skill Contract (P, O, A, V, F), organizes skills with a Hierarchical Skill Ecosystem Graph, and diagnoses library health across utility, compatibility, risk, and validation dimensions. Given a raw skill library, SkillOps produces a maintained library that can be used by existing retrieval or planning agents without changing their internal code. On ALFWorld, SkillOps achieves 79.5 percent task success as a standalone agent, outperforming the strongest baseline by 8.8 percentage points with no additional task-time large language model calls. As a plug-in layer, it improves retrieval-heavy baselines by 0.68 to 2.90 percentage points. The current rule-based maintenance implementation uses nearly zero library-time large language model calls or tokens, showing that skill-library maintenance can be added as a low-overhead architectural layer.

### 1. 核心问题与研究动机
*   **核心问题**：论文识别并定义了**“技能技术债”（Skill Technical Debt）**。随着 LLM 智能体运行时间的增加，其技能库会因为不断添加、修补和重用技能而积累冗余、接口漂移、验证缺失或实现陈旧等缺陷。
*   **研究动机**：现有的研究（如 Voyager, ToolLLM）主要关注“任务时”（Task-time）的检索、规划和修复，即如何用好现有技能。然而，如果技能库本身存在缺陷，任务时的修复往往是临时性的，无法根除库级别的持久性问题。
*   **整体含义**：提出将技能库视为一个**自维护的软件生态系统**，通过在“库维护时”（Library-time）进行系统性的诊断和修复，提升智能体的长期鲁棒性和效率。

### 2. 方法论：SkillOps 框架
SkillOps 采用了一种双环架构，将技能库管理解耦为任务执行和库维护两个阶段：

*   **核心思想**：
    1.  **技能契约（Skill Contract）**：将每个技能表示为五元组 $(P, O, A, V, F)$，分别代表前置条件、执行操作、产出物、验证器和已知故障模式。
    2.  **层级技能生态图（HSEG）**：在技能间建立四种类型的边：依赖（dep）、兼容（comp）、冗余（red）和替代（alt）。
*   **关键技术细节**：
    *   **任务时循环（Task-Time Loop）**：基于 HSEG 进行约束规划。它不仅匹配语义，还检查接口兼容性，并在必要时自动插入适配器（Adapter）或验证器（Validator）。
    *   **库时循环（Library-Time Loop）**：根据执行日志进行**五维健康诊断**（效用、冗余、兼容性、故障风险、验证间隙）。
    *   **维护动作**：执行合并（merge）、修复（repair）、退役（retire）、添加验证器和添加适配器等操作。
    *   **CGPD 算法**：一种基于收缩映射原理的风险传播算法，能够将上游技能的风险传播至下游，实现预防性维护。

### 3. 实验设计
*   **数据集/场景**：主要在 **ALFWorld**（基于文本的家庭操纵任务基准）上进行评估。
*   **技能库构建**：使用 **SkillsBench** 的 229 个真实技能作为基础，并通过注入合成噪声（如冗余克隆、接口错误等）将库规模扩展至 2000 个技能，模拟真实的技术债环境。
*   **对比方法（Baselines）**：
    *   **ReAct**：全量 Prompt 注入。
    *   **LLM_Skill_Planner**：基于 GPT-4o-mini 的语义排名规划。
    *   **Hybrid_Retrieval**：结合 BM25 和向量检索。
    *   **GoS_Style**：类似 Graph-of-Skills 的依赖图检索。
    *   **SkillWeaver**：具有任务时自我修复能力的先进基准。

### 4. 资源与算力
*   **硬件资源**：实验在一台配备 **3 张 NVIDIA RTX 2080 Ti (11GB)** GPU 和 3 颗 Intel Xeon CPU 的机器上运行。
*   **模型调用**：所有 LLM 推理均通过 OpenAI API 调用 **gpt-4o-mini** 完成。
*   **成本与时长**：全量评估耗时约 6 小时，总 API 成本仅为 **0.27 美元**。论文强调其基于规则的维护逻辑在库维护阶段几乎产生零 LLM 调用开销。

### 5. 实验数量与充分性
*   **实验规模**：涵盖了从 200 到 2000 个技能的 **9 种不同库规模**。
*   **重复性**：每个实验设置均使用 **3 个独立随机种子**运行，并报告了均值、标准差及 95% 置信区间。
*   **消融实验**：详细测试了任务时循环、库时循环、外部图结构、内部契约结构以及各项维护动作（如适配器、验证器插入）对性能的影响。
*   **充分性评价**：实验设计非常全面，不仅验证了 SkillOps 作为独立智能体的优越性，还验证了其作为“插件层”增强其他检索方法的效果，并深入分析了 Token 消耗和检索 Top-k 的敏感性。

### 6. 主要结论与发现
*   **性能领先**：在 ALFWorld 上，SkillOps 达到了 **79.5%** 的成功率，比最强基准高出 **8.8 个百分点**。
*   **插件增益**：作为插件层，SkillOps 为重检索型基准带来了 **0.68% 至 2.90%** 的性能提升。
*   **低开销维护**：基于规则的维护 pass 几乎不消耗 LLM Token，且由于清理了冗余技能，任务时的 Token 消耗通常会降低（最高降低 3.95%）。
*   **抗噪声能力**：随着技能库规模增大和噪声比例增加（15% 到 90%），SkillOps 的性能保持稳定，而传统检索方法性能大幅下降。

### 7. 优点与亮点
*   **架构创新**：首次将软件工程中的“技术债”概念引入 LLM 技能管理，提出了“库时维护”这一被忽视的维度。
*   **低成本高效率**：通过结构化契约和图规则替代昂贵的 LLM 推理进行库维护，具有极高的实用价值。
*   **通用插件化**：设计为方法无关（Method-agnostic）的层，可以无缝集成到现有的智能体框架中。

### 8. 不足与局限
*   **依赖结构化输入**：SkillOps 目前依赖于结构化的技能契约（类似 PDDL 的参数），在完全非结构化的真实环境中，提取这些契约本身可能面临挑战。
*   **实验场景单一**：主要集中在 ALFWorld 这一模拟环境，且技能库包含大量合成噪声，在真实世界复杂 API 环境下的表现仍需进一步验证。
*   **语义理解限制**：当前的 V4 版本主要依赖规则，可能无法处理需要深度语义推理的复杂技能冲突。
