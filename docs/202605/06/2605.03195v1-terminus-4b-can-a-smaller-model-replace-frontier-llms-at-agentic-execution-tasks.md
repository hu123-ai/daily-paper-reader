## 摘要
现代编程智能体越来越多地将专门的子任务委托给子智能体，这些子智能体是更小、更专注的智能体循环，负责处理搜索、调试或终端执行等特定职责。这种架构模式通过将冗长的输出（如构建日志、测试结果等）隔离在子智能体上下文中，从而保持主智能体的上下文窗口整洁。通常，当智能体为此类任务使用子智能体时，会采用前沿模型作为子智能体。在本文中，我们研究了经过微调的小语言模型（SLM）在智能体终端执行任务中是否能达到与前沿模型相当的性能。我们提出了 Terminus-4B，这是一个专门针对该任务，通过监督微调（SFT）和使用基于准则的 LLM-as-judge 奖励的强化学习（RL）进行后训练的 Qwen3-4B 模型。在涵盖各种前沿模型、训练消融实验和主智能体配置的广泛评估中，我们发现，与无子智能体基线相比，Terminus-4B 能够将主智能体的 token 使用量减少高达约 30%，且不会影响智能体在 SWE-Bench Pro 和我们内部的 SWE-Bench C# 基准测试（该基准测试通常包含大量冗长的执行任务）中的性能。此外，Terminus-4B 改进了关键指标，表明主智能体更加依赖子智能体的输出，并减少了自身执行终端任务的次数。我们观察到，我们的模型不仅缩小了原始 Qwen 模型与 Claude Sonnet / Opus / GPT-5.3-Codex 等前沿模型之间的差距，甚至往往在性能上有所超越。

## Abstract
Modern coding agents increasingly delegate specialized subtasks to subagents, which are smaller, focused agentic loops that handle narrow responsibilities like search, debugging or terminal execution. This architectural pattern keeps the main agent's context window clean by isolating verbose outputs (e.g. build logs, test results, etc.) within the subagent context. Typically when agents employ subagents for such tasks, they use frontier models as these subagents. In this paper, we investigate whether a finetuned small language model (SLM) can achieve comparable performance to frontier models in the task of agentic terminal execution. We present Terminus-4B, which is a post-trained Qwen3-4B model via Supervised Finetuning (SFT) and Reinforcement Learning (RL) using rubric-based LLM-as-judge reward, specifically for this task. In our extensive evaluation spanning various frontier models, training ablations and main agent configurations, we find that Terminus-4B is able to reduce the token usage of the main agent by up to ~30% compared to the No Subagent baseline with no impact to agent performance on benchmarks like SWE-Bench Pro and our internal SWE-Bench C# benchmark, which tends to be heavy in verbose execution tasks. Furthermore, Terminus-4B improves key metrics showing the main agent relying on the outputs of the subagent and doing fewer terminal execution tasks by itself. We see that our model not only closes the gap between the Vanilla Qwen model and frontier models like Claude Sonnet / Opus / GPT-5.3-Codex, but often even exceeds their performance.

*   **核心问题**：现代编程智能体在执行构建、安装依赖和运行测试时，终端输出（如冗长的构建日志、测试结果）会迅速填满主智能体的上下文窗口（Context Window），导致推理效率下降、成本增加且容易丢失关键信息。
*   **研究动机**：
    *   **上下文冗余**：终端输出往往是智能体轨迹中最大的 Token 消耗源。
    *   **架构优化**：采用“主智能体-子智能体”模式，将执行任务委派给子智能体，由其吸收冗长输出并仅返回精简摘要。
    *   **成本与效率**：目前这类子任务通常仍由昂贵的前沿模型（如 Claude 3.5/GPT-5 等）承担，研究旨在验证 4B 规模的小模型是否能胜任这一特定任务。

### 2. 方法论
*   **核心思想**：开发 **Terminus-4B** 模型，通过两阶段后训练（Post-training）使其专注于终端执行和结果摘要。
*   **关键技术细节**：
    *   **模型基础**：基于 Qwen3-4B-Instruct。
    *   **第一阶段：有监督微调（SFT）**：使用从内部遥测数据中提取的专家轨迹进行微调，让模型掌握终端工具调用规范和摘要格式。
    *   **第二阶段：强化学习（RL）**：采用 **GRPO（群组相对策略优化）** 算法。
        *   **解耦训练框架**：为了降低训练成本，将子智能体从主智能体循环中解耦，使用轻量级模型作为主智能体发送预设查询。
        *   **基于准则的奖励设计（Rubric-based Reward）**：引入 LLM-as-judge，从执行质量（7个维度）、失败模式（4个维度）和最终答案质量（3个维度）共 14 个维度对生成的“执行计划”进行评分。
    *   **工具限制**：子智能体仅被授予 `Terminal` 工具，且有严格的轮次限制（默认 10 轮）和强制的 XML 格式输出要求。

### 3. 实验设计
*   **数据集/场景**：
    *   **训练集**：涵盖 TypeScript, C#, Java, JavaScript, Python 等 5 种语言，涉及 2144 个仓库。
    *   **测试基准**：**SWE-Bench Pro**（多语言、长时程任务）和内部的 **SWE-Bench C#**（侧重重型执行任务）。
*   **对比方法（Baselines）**：
    *   **无子智能体**：主智能体直接调用终端。
    *   **前沿模型子智能体**：使用 Claude Opus/Sonnet 作为子智能体。
    *   **Vanilla SLM**：原始 Qwen3-4B 模型。
    *   **SFT-only SLM**：仅经过微调但未进行 RL 的模型。
*   **主智能体配置**：分别测试了 GPT-5.3-Codex、Claude Sonnet 4.6 和 Claude Opus 4.6 作为主智能体时的表现。

### 4. 资源与算力
*   **硬件**：使用单节点，配备 **8 台 NVIDIA A100/H100 GPU**。
*   **训练细节**：
    *   SFT 阶段：训练 2 个 Epoch，学习率 $2 \times 10^{-5}$。
    *   RL 阶段：使用 GRPO，每组采样 8 个 Rollouts，KL 惩罚系数 $\beta=0.02$。
*   **推理**：部署在 Fireworks 平台上进行快速推理。

### 5. 实验数量与充分性
*   **实验规模**：论文进行了广泛的评估，包括在两个大型基准测试上的端到端表现、跨语言泛化测试、跨主智能体模型测试。
*   **消融实验**：
    *   **工具移除实验**：移除主智能体的终端工具，强制所有执行流经子智能体，以“压力测试”子智能体的独立能力。
    *   **LLM-Judge 评分**：从主智能体视角对子智能体响应的“可操作性”和“准确性”进行 5 维度打分。
*   **客观性**：实验设计考虑了主智能体对子智能体的“不信任感”（即主智能体在子智能体运行后是否又重复运行相同命令），这一指标非常客观地反映了小模型的实际效用。

### 6. 主要结论与发现
*   **Token 节省**：Terminus-4B 相比无子智能体基线，可减少主智能体约 **30% 的 Token 消耗**。
*   **性能持平/超越**：在解决率（Resolve Rate）上，Terminus-4B 达到了与前沿模型（Opus/Sonnet）作为子智能体时相当的水平，显著优于原始 Qwen3-4B。
*   **行为改善**：经过 RL 训练后，主智能体重复执行终端命令的比例大幅下降，表明主智能体能够信任并有效利用 Terminus-4B 返回的摘要。
*   **SFT 的必要性**：实验证明，如果没有 SFT 直接进行 RL，模型无法掌握基本的任务格式，导致训练失败。

### 7. 优点与亮点
*   **架构实用性**：针对编程智能体最痛的“上下文膨胀”问题提出了切实可行的子智能体方案。
*   **奖励机制创新**：多维度的 Rubric 评分比简单的二元成功/失败奖励提供了更丰富的信号，解决了执行任务难以定义“唯一正确答案”的问题。
*   **成本效益**：证明了 4B 规模的模型在特定垂直领域（终端执行）可以替代顶级大模型，具有极高的商业应用价值。

### 8. 不足与局限
*   **平台局限性**：训练和评估主要集中在 Unix/Bash 环境，未覆盖 Windows PowerShell 或 macOS Zsh 等其他常见环境。
*   **模型单一**：仅在 Qwen3 系列上进行了验证，未测试其他 SLM 家族（如 Llama 或 Phi）的迁移效果。
*   **评估环境**：主要基于 Docker 化的 SWE-Bench 环境，可能无法完全模拟现实开发中极其复杂、非标准化的配置问题。
